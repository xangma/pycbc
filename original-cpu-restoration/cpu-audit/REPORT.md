# Bounded audit: original CPU preservation

Baseline: `40e94792b3edf59f39b18b65102b28a4f74433a7`.
Published main: `1d22031fd31c6e5bcb48a68fe11772e960bd406b`.
Rebuilt candidate reviewed: `652206d84177f658f5fb2f9cab2ee73f6d2bc95f`.

**The four precision reversions do not restore all original CPU behavior.** The independent changes below remain in the candidate. For a strict preservation requirement, restore baseline CPU paths before pinning the runtime candidate. Several changes repair baseline bugs; that does not satisfy a requirement to preserve the baseline. This report does not establish additional numerical drift in a qualified production run.

All line numbers below refer to immutable candidate blobs, not the current checkout. Obtain them with `git show 652206d84177f658f5fb2f9cab2ee73f6d2bc95f:<path>`. Published-to-candidate differences are exactly the four known production files and three precision tests, confirming the other findings survive reconstruction.

## Evidence and scope

- `probe_cpu_semantics.py` reads only pinned Git blobs and executes isolated extracted functions with NumPy 2.3.5. `probe-results.json` records four demonstrated differences. It uses minimal stand-ins for vectors, CPU dispatch and the unused framework context, and NumPy FFT/Hann for the PSD completion path. These are control-flow/NumPy probes, not integration or numerical qualification tests.
- `audit_ast.py`, `ast-inventory.json`, and per-file normalized diffs compare baseline/corrected baseline with published main. They remove string-expression documentation and formatting noise. Their main pin is deliberately the published commit; candidate findings were separately checked against `652206d`, and the seven-file published-to-candidate diff was verified.
- Focused source review found no additional changed CPU numerical formula in the reviewed Welch, inverse-spectrum truncation, PSD interpolation, overwhitened-data CPU branch, ordinary sample-frequency/time grids, and ordinary sky-max formulas. CPU `squared_norm` and no-argument `cumsum` still route to the original CPU implementations. This is bounded review, not an exhaustive claim covering every modified function or NumPy protocol extension.
- The four known precision corrections were excluded from this audit's restoration work. No new Torch modules were broadly audited. Full Linux/MKL/FFTW runtime checks remain with the primary qualification work.
- `git diff --name-only` baseline-to-candidate reports no changes under `pycbc/lib` or matching `*.c`, `*.cc`, `*.cpp`, `*.cu`, `*.cuh`, `*.pyx`, `*.pxd`.
- This audit changed only new files in this artifact directory. Root tracked status is clean; branches and remote state were not changed. No background commands remain.
