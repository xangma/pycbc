Inference: the blocking CPU-scalar-to-device normalization conversion at the end of χ² waits for preceding queued χ² work. Its host duration does not mean scalar transfer itself costs a millisecond. Hoisting this conversion before `shift_sum`, or reusing an exact-dtype per-template/PSD device normalization tensor, can remove an accidental barrier from this point. Preserve `as_tensor(..., dtype=chisq_t.dtype)` and `(snr_norm_t**2)` expression semantics; replacing these with a Python pre-squared scalar changes rounding. Differentiable norm tensors must remain tensors with their graph/tangent intact.

## Ranked experiments and missing evidence

1. **Hoist/prepare exact-dtype χ² normalization metadata.** Instrument normalization transfer before/after `shift_sum`, distinguish scalar upload API time from outstanding kernel completion, and measure downstream waits. Preserve every scientific operation and AD route.
2. **Plan immutable χ² and threshold geometry once per valid key.** Record hits/evictions, point-count histogram, PSD identity, device/dtype/length, and separate single-point/multipoint launch counts. Avoid unsafe correlation/phase result caching or numerical route changes.
3. **Bounded bank prefetch and metadata staging.** Separately measure HDF group/data/attribute reads, host conversion, HtoD bytes by callsite, device indexing/weights, allocation and first-use compilation. Measure staging lifetime and total peak host/device memory; keep expanded waveform ownership distinct.
4. **Offline fixed-shape graph or several-segment batching.** Record cold capture, warm replay, sparse compaction/export and exact workload parity. This requires independent correlation/SNR storage until each segment's χ² completes; the current shared scratch makes blind reordering invalid. Do not equate the separate live peak/batch API with this offline workload.

Remaining missing measurements are specifically: source-level callsite labels/input shape and dtype metadata beyond the resolved CPU-op→runtime→device linkage; all-transfer per-range byte totals beyond the sync-linked transfers; single-point and multipoint completed device/host distributions; cold vs subsequent template/operator cost; host scheduling and launch gaps with queued work accounted for; full unprofiled repeated workers and an independently defined warm filtering timer with a completion fence; allocation/staging peak memory; and delayed-current-stream/side-stream host-read plus workspace-reuse regression checks. Keep identical 384 templates, five segments, 1,904 valid seconds, 16 χ² bins and existing comparator budgets. A profiling boundary must wait for completion, though internal device dependencies should use the least-broad correct stream/event ordering.
