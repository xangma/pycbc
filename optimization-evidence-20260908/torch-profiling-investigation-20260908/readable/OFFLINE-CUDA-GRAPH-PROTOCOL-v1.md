# Offline CUDA graph protocol v1

This protocol freezes the scientific and timing decision for one artifact-only offline CUDA graph trial. It applies to clean source ecd5d08231d8ce0a938bc31cfde27c9a5d6f901f. The owner prepares the artifact helper/harness and is the sole len operator. The independent reviewer validates source, frozen inputs, raw results and terminal closure locally. No source, kernel, precision, tolerances, production defaults, batching or execution order changes are authorized by this protocol.

## Arms and exact change

E = eager CUDA with the accepted fast descriptor reuse. G = corrected offline graph CUDA with the identical accepted fast descriptor reuse. Both use the same clean source and common runner/import/construction point; graph capture/replay hooks are installed only for G. Neither arm enables live-batch, on-device-peak, compilation or other new gates. Both retain all original scientific operations and the same executable argument vector. Environment, source, native libraries, helpers, references and workload files are hash-pinned before the first diagnostic launch. The companion JSON pins the existing six reference files and exact geometry; owner input-manifest pins the completed new helper/harness/protocol before launch.

The only graph numerical correction is a persistent raw float32 threshold input and persistent float32 squared output: fill raw with the current Python threshold, then capture `torch.mul(raw, raw, out=squared)` before existing fixed-shape clustering. Each graph retains these tensors and its scratch for its lifetime. Correlation/IFFT kernels and sparse compaction/gather are unchanged. Three warmups per graph precede capture, exactly as the existing path. The normal executable calls replay after first-call capture, including on the first segment call. No alternate uncorrected graph performance arm is needed.

## Closed eligibility and ownership

At the matched-filter control boundary, bind one Torch CUDA device, positive integer clustering window, exact control/correlator/IFFT/clusterer identities and one calling thread/current execution stream. Original eager supports more general callers; this artifact trial does not qualify them. Require base strided contiguous complex64 tensors with no reverse/forward AD, inference state, lazy conjugate/negative views or subclasses. Require valid single-row storage spans and original nonoverlapping correlation and SNR buffers. Shared views are intentional: correlator x aliases the designated cutoff slice of common template storage, y aliases its segment cutoff slice, z aliases common correlation cutoff storage, and each clusterer series aliases its own analysis slice of common SNR storage. Pin actual pointers plus storage pointers, byte offsets, sizes/shapes/strides/dtypes/devices, slices, cutoffs and FFT engine binding. Template values may change; these identities may not.

Bind one graph per segment, with its original positive integer window and scratch. Exactly five independent segment graph entries are permitted; their analyzed lengths differ at the last segment. Do not reuse an old graph after scratch replacement, window change or tensor rebinding. Raw threshold changes are supported through the retained tensor. Template and segment input producers, raw-threshold fill, graph launch and downstream consumers must be ordered on the bound current execution stream. Capture uses the existing side-stream wait in both directions. Default and explicit custom current streams are tested with separate fresh control lifetimes; changing an already-bound control's current stream is outside the fixed trial.

Qualification checks every call and negative fixture before replay. Timing retains only common setup and boundary provenance checks, without per-call signatures, counters, clocks, tracing or full-output reads. The complete fixed workload and unchanged control flow justify this bounded measurement; this is not a claim of general runtime guarding or production readiness.

Graph/correlation/SNR scratch cannot be overwritten before the preceding segment's veto and trigger consumers have used it. Keep the executable's sequential segment/template order. Sparse returned indices and values must own separate advanced-indexed storage and remain unchanged after later replay, different segment, changed template and scratch reuse. Full correlation/SNR results deliberately alias shared scratch; compare/snapshot them before the next call rather than claiming persistence. Retain graph input/scratch objects through queued completion; close at the successful executable boundary after outstanding work is complete, and include graph release, descriptor frees/restoration, receipts and interpreter exit in full-process wall. Preserve primary failures through cleanup.

## Native CUDA regression gate

Run one fresh untimed CUDA diagnostic process before executable qualifications. CUDA/Triton unavailable, graph capture failing, an unasserted return or eager fallback is a failure, not a skip/pass. Record actual capture and replay observations outside timed workers.

1. Exercise actual CUDA block-reduction/mask kernels on an interior isolated candidate with threshold `1.00000003` and complex64 sample `(1, 0.0003452669770922512)`. Assert old graph square-before-conversion rejects while eager and corrected graph keep exactly the same index/value. Pin fixture values, squared-threshold bytes and output bytes. This must demonstrate baseline-fail/candidate-pass; the local NumPy counterexample alone does not qualify CUDA behavior.
2. Repeat with adjacent representable thresholds, exact equality, threshold zero, above-all threshold, separated survivors in every eligible cluster, no survivors, tied adjacent blocks/plateaus, and NaN/infinity samples. Compare against unchanged eager CUDA semantics, including strict threshold and tie handling, without inventing new special-value expectations. Exercise repeated threshold updates on one capture.
3. On real full matched-filter controls, change template contents, normalization and segment selection over repeated replay. Compare full correlation/SNR bytes, norm, selected index/value bytes and zero-result shape/contract against eager before scratch reuse. Retain sparse arrays across later graph calls/template overwrite and assert their bytes remain unchanged. Run on default and explicit custom current streams with queued producers and proper consumer completion.
4. Use isolated negative fixtures to mutate window/scratch, tensor pointers/bindings, shape/stride/dtype/device, lazy/AD/inference/subclass state and current stream. The qualification preflight must reject each before invoking replay; record unchanged replay count. This is a harness contract test, not a new production fallback claim.

## Complete executable qualification

Run fresh serial E qualification, then G qualification after the native gate. E passes the existing frozen CUDA own-scheme reference. In G, each of the 1,920 normal calls first takes an eager snapshot for that same current template, segment and norm, then compares graph output before allowing downstream executable processing. Each per-call comparison includes full correlation/SNR bytes, returned norm and sparse results, including empty-result paths. Diagnostics cannot add extra graph replays to the counted normal-call total. Require exactly five successful captures and 1,920 actual replays, all eligibility/storage/geometry/stream checks passing, varied template content/norm evidence, and exact retained sparse output checks.

Record three warmups per graph, capture and first-use costs, peak/allocated/reserved device memory and release evidence only in qualification. Do not interpret instrumented eager-plus-graph qualification time as performance. Require 384 templates, five 512-second transforms of 2,097,152 samples at 4,096 Hz, 1,904 unique valid seconds, 16 chi-square bins, identical PSD/conditioned strain and exact segment geometry from the companion JSON. The first four SNR analyze slices are [458752:2019328]; the fifth is [475136:2031616]. The configured cluster window is one second, so validate the actual control call window is 4,096 samples. Record and match original frequency cutoffs rather than guessing them.

Both qualification outputs must match all 18 H1 scientific datasets byte-for-byte within CUDA against each other and their frozen reference. Both also pass the unchanged default comparator against the accepted standard-cached reference. Any call/source/runtime/science/lifetime failure stops before timing and remains a failed campaign. The accepted descriptor helper and its native identities remain unchanged; both arms report three owned descriptors freed once, restored functions and no lifecycle errors.

## Prespecified timing and acceptance

After all gates pass, run eight fresh serial subprocesses in exactly these four pairs:

1. E1, G1
2. G2, E2
3. G3, E3
4. E4, G4

Every arm appears first twice. No excluded warmup processes, adaptive sample extension, timing hooks or profiler. The native/qualification gates have already warmed some filesystem/library caches, so this is not cold-cache evidence. Each timed child imports/constructs the same common helpers, runs the actual full executable, and includes interpreter/import/common setup, CUDA initialization, graph warmup/capture, all filtering/veto/output work, required completion and cleanup in measured full child wall. Retain every run and source/runtime/memory-independent boundary receipt.

Every timed output must be byte-equal in all 18 H1 science datasets to its qualification and the paired contemporaneous arm, and pass the unchanged standard-cached default comparator. Preserve all native pools at one, Torch intra/inter-op one, core-8 affinity, source/native/helper/input/reference hashes and workload counters. Timing cannot fall back to eager unnoticed: the timed helper is the exact qualified graph code, and its final graph table must contain the same five live graph entries and fixed identities without per-call instrumentation.

Let E_i and G_i be whole-child wall seconds. Accept a bounded performance gain only if every gate passes, all four paired differences E_i - G_i are strictly positive, and median(G) < median(E). Report every raw value, medians/ranges, all differences and G_i/E_i ratios, and percentage reduction 100*(1-median(G)/median(E)). Setup/internal telemetry is secondary. Otherwise reject or mark no demonstrated benefit, preserving all samples. Four pairs do not support a significance or generalization claim. A warm replay improvement alone cannot pass this whole-process gate. No standard or Torch-CPU speedup/parity claim follows from this GPU-only trial.
